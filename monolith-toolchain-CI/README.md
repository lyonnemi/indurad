# ROOTFS Compatibility Validation Pipeline

This repository builds the _monolith_ with a pre-defined set of indurad ROOTFS toolchains.

The toolchain CI builds the following platforms:

* `local` (use current build image)
* `androidarm64v8a`
* `androidx64`
* `amd64generic`
* `automation`
* `ct20`
* `i686generic`
* `ildrv2`
* `ildrv3`
* `microbox`
* `te0803`
* `ultrascale`

For each platform, the toolchain CI builds the latest patch release of all minor versions.  
For each `platform` and `toolchain-version` combination, a build gets queued for `C++20`.

## Configuration

To run the toolchain CI once for a specific monolith,
click [here](https://softfs-self-service.indurad.x/project/monolith-toolchain-ci),
select the monolith project and revision to build and press `Start build`.

Maintainers of this project can also start a pipeline directly
[here](https://git.indurad.x/master/monolith-toolchain-CI/-/pipelines/new).

To periodically run the toolchain CI:
1. click [here](https://git.indurad.x/master/monolith-toolchain-CI/-/pipeline_schedules/new) to create a new pipeline schedule
2. configure the following variables (documented [here](toolchain_ci/parent_pipeline/gitlab-ci.yml)):
   * `TOOLCHAIN_CI_MONOLITH_PROJECT`
   * `TOOLCHAIN_CI_MONOLITH_REVISION`
   * `TOOLCHAIN_CI_PLATFORMS_TO_BUILD`
   * `TOOLCHAIN_CI_MIN_TOOLCHAIN_VERSION`
   * `TOOLCHAIN_CI_MAX_TOOLCHAIN_VERSION`
   * `TOOLCHAIN_CI_CXX_VERSIONS`

## CI-Pipeline Structure

The toolchain CI is split into two CI pipelines:

1. the [parent pipeline](toolchain_ci/parent_pipeline/gitlab-ci.yml)
    * `Run tests`
      * runs unit-tests.
    * `Resolve monolith revision`
      * determines the actual commit hash to build.
      * (project `master/monolith` + revision `v13.x` -> commit hash)
    * `Generate CI config`
      * uses the results of `Resolve monolith revision`
      * generates the downstream pipeline configuration.
    * `Toolchain CI`
      * Uses the results of `Generate CI config`.
      * Triggers the downstream pipeline.
2. the [downstream pipeline](toolchain_ci/parent_pipeline/generate_toolchain_ci/templates/gitlab-ci.yml)
   * `Dummy job`
     * Used to create an empty downstream pipeline.
     * This is a workaround for GitLab having no support for conditional downstream pipelines.
   * `Toolchain buildjob`
     * Builds a dummy SoftFS for a given platform, toolchain, monolith revision and C++ version.
     * Example: `icharlie 18.2.1 on amd64generic (C++20)`
   * `Generate report`
     * Uses the results of all jobs of type `Toolchain buildjob`.
     * Receives build reports from all SoftFS build jobs.
     * Generate an HTML report summarizing all build results.

### CI-Pipeline Workflow

#### Upstream Pipeline

1. The parent pipeline gets triggered with `TOOLCHAIN_CI_MONOLITH_PROJECT` and `TOOLCHAIN_CI_MONOLITH_REVISION`
   as input variables
2. `Run tests` and `Resolve monolith revision` run simultaneously
3. `Resolve monolith revision` sets `MONOLITH_COMMIT_SHA` to the actual monolith commit hash
4. `Generate CI config` generates the downstream pipeline configuration
5. `Toolchain CI` triggers the downstream pipeline

#### Downstream Pipeline

1. The downstream pipeline gets triggered with the configuration generated by `Generate CI config`.
   No variables are passed from the upstream pipeline to the downstream pipeline:
   the downstream pipeline configuration file is self-sufficient (no job variables).
2. If `Generate CI config` detected that the monolith revision was already built,
   only `Dummy job` gets started.
   `Dummy job` does nothing and terminates. The pipeline ends here.
3. Otherwise, several generated toolchain build jobs (see `.build_toolchain_softfs`) run simultaneously.
4. After all toolchain build jobs completed,
  `Generate report` starts, receives their artifacts (`target-list.###.json`)
  and generates a summarizing HTML report.

## Folder Structure

- `toolchain_ci`: CI Configuration and scripts facilitating the toolchain CI.
  - `parent_pipeline`: Resolves the monolith revision, scans for toolchains and generates `downstream_pipeline`.
    - `resolve_monolith_revision`
      - Determines which monolith commit hash to build ("master" → Commit hash).
    - `generate_toolchain_ci`
      - Generates the YAML configuration for the toolchain CI pipeline.
      - Depends on `resolve_monolith_revision` and the output it generates.
  - `downstream_pipeline`: Actual toolchain CI, builds the monolith with various toolchains and generates a
    summary report.
    - `format_calvin_conf`
      - Creates a `calvin.conf` with the correct toolchain, platform and monolith module.
    - `target_list`
      - Creates a summary of built targets for a single toolchain build.
    - `compatibility_report`
      - Generates the HTML report at the end of the toolchain CI pipeline.
      - Depends on `target_list` and on the output it generates.

## Dependencies
